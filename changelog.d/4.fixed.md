Consume the clause-parameter pairs and declare the probes core now gates on, so the dialect stops dropping clauses and stops rendering SQL the server rejects. `DROP VIEW` refuses both `CASCADE` and `RESTRICT` by name (both were silently dropped), `DROP MATERIALIZED VIEW` refuses `RESTRICT` by name (its `CASCADE` refusal already existed), `DROP TABLE ... CASCADE`/`RESTRICT` and `CREATE TABLE ... AS ... WITH [NO] DATA` refuse instead of rendering server-rejected SQL (the drop-table probes moved to `ClickHouseTableMixin`, where core's generic `True` can no longer shadow them), `TRUNCATE ... RESTRICT`/`CONTINUE IDENTITY` refuse by name (the `CASCADE` and `RESTART IDENTITY` refusals already existed), and the repaired `REFRESH MATERIALIZED VIEW` gate no longer refuses every refresh: unspecified renders `SYSTEM REFRESH VIEW`, explicit `WITH [NO] DATA` is refused by name, and `WAIT` still appends `SYSTEM WAIT VIEW`. `CREATE MATERIALIZED VIEW ... WITH [NO] DATA` and `CTE AS NOT MATERIALIZED` are refused by name (`AS MATERIALIZED` still renders), and transaction `WAIT`/`NO WAIT` are refused by that spelling before the blanket transaction refusal. The identity clause and the bare `AUTO_INCREMENT` marker are refused from core's fail-closed mixins because `supports_identity_column()` and `supports_auto_increment_column()` answer `False` (both mechanisms are Code 62 on ClickHouse 26.7, measured). `supports_materialized_cte()` is declared `True` on `ClickHouseCTEMixin`; `supports_with_data_clause()` and `supports_transaction_wait()` are declared `False` on `ClickHouseMaterializedViewMixin` and `ClickHouseTransactionMixin`; `supports_drop_table_cascade`/`supports_drop_table_restrict` are declared `False` on `ClickHouseTableMixin`; `supports_truncate_restrict` and `supports_restrict_view` are stated explicitly.
