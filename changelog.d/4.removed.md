Remove the DDL ClickHouse cannot run, rather than declining it after rendering. Core's `SequenceMixin` is left out of `ClickHouseDialect`'s base list, so `supports_sequence()` and the option-level probes (`supports_sequence_if_not_exists`, `supports_sequence_if_exists`, `supports_sequence_start`, `supports_sequence_increment`, `supports_sequence_minvalue`, `supports_sequence_maxvalue`, `supports_sequence_cycle`, `supports_sequence_cache`, `supports_sequence_order`, `supports_sequence_owned_by`) are gone and asking raises `AttributeError`; the package's own `supports_create_sequence()` and `supports_drop_sequence()` remain and answer `False`. `CreateSequenceExpression`, `AlterSequenceExpression` and `DropSequenceExpression` now raise `UnsupportedFeatureError` naming the missing formatter instead of rendering `CREATE SEQUENCE ...` for a server that answers Code 62, and the dialect no longer meets `CreateSequenceSupport`, `AlterSequenceSupport` and `DropSequenceSupport`. Naming is a separate capability and is untouched: `SequenceNameMixin` stays, so `Sequence(dialect, "s").to_sql()` still renders the identifier. The same applies to schemas, which ClickHouse spells as databases: `supports_schema()`, `supports_create_schema()`, `supports_drop_schema()`, `supports_schema_if_not_exists()` and `supports_schema_if_exists()` are gone, and `CreateSchemaExpression` / `DropSchemaExpression` refuse at dispatch. Migration: use the database probes and database DDL, or catch `UnsupportedFeatureError`.
