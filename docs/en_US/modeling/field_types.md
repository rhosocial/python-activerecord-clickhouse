# Field type mapping

ClickHouse is a strongly typed columnar database; every column has a precise type.
This backend maps Python types to ClickHouse column types.

## Basic mapping

| Python type | ClickHouse column type | Notes |
|-------------|------------------------|-------|
| `int` (primary key) | `Int64` | PK generated by snowflake, fixed `Int64` |
| `int` (normal) | `Int32` | signed 32-bit |
| `int` (wide range) | `Int64` | annotate `int64` |
| `float` | `Float64` | double precision |
| `str` | `String` | unlimited length |
| `bool` | `Bool` | alias of `UInt8` (native `Bool` in ClickHouse 21+) |
| `bytes` | `String` | bytes stored as `String` |
| `datetime.datetime` | `DateTime64(6)` | microsecond-precision timestamp |
| `datetime.date` | `Date` | date |
| `decimal.Decimal` | `Decimal(p, s)` | precision and scale required |
| `uuid.UUID` | `UUID` | native UUID |
| `ipaddress.IPv4Address` | `IPv4` | native IPv4 |
| `ipaddress.IPv6Address` | `IPv6` | native IPv6 |

## Composite types

ClickHouse's columnar composite types are its strength:

| Python shape | ClickHouse column type | Example |
|--------------|------------------------|---------|
| `list[int]` | `Array(Int32)` | tag array |
| `list[float]` | `Array(Float32)` | embedding vector (replaces MySQL `VECTOR`; use with `L2Distance`) |
| `list[str]` | `Array(String)` | string array |
| `dict[str, str]` | `Map(String, String)` | key-value map |
| `dict[str, int]` | `Map(String, Int32)` | counter map |
| `tuple` | `Tuple(...)` | fixed-structure tuple |
| `enum.Enum` | `Enum8` / `Enum16` | enum (8/16-bit) |

## Special types

| ClickHouse type | Use | Notes |
|-----------------|-----|-------|
| `Nullable(T)` | allows NULL for `T` | see [Nullable & optional fields](nullable.md) |
| `LowCardinality(T)` | dedup storage for low-cardinality | significantly reduces storage/increases speed when enum values are few |
| `FixedString(N)` | fixed-length string | e.g. fixed-length codes |
| `JSON` | native JSON type | query with `JSONExtract*` |
| `Date32` | date range 1970–2149 | wider range than `Date` |
| `Decimal32/64/128` | fixed-point | choose width by range |

## Declaring types on a model

An ActiveRecord model declares fields with Pydantic annotations; the backend
infers ClickHouse column types from them:

```python
from typing import Optional
from pydantic import Field
from rhosocial.activerecord.model import ActiveRecord

class Event(ActiveRecord):
    __table_name__ = "events"
    __primary_key__ = "id"

    id: Optional[int] = None                  # Int64 (snowflake ID)
    user_id: int                              # Int32
    amount: float                             # Float64
    tags: list[str]                            # Array(String)
    counters: dict[str, int]                   # Map(String, Int32)
    created_at: Optional["datetime"] = None   # Nullable(DateTime64)
```

## Unsupported types (fail-fast)

The following MySQL/other-DB types are **not** exposed by the ClickHouse backend;
related expressions fail fast:

- Spatial types: `GEOMETRY`/`POINT`/`LINESTRING`/`POLYGON`/... → store WKT as `String`
- `VECTOR` (MySQL 9.0) → `Array(Float32)`
- `SET` → `Enum16` or `Array(String)`
- `BLOB`/`TEXT` (MySQL) → `String`
